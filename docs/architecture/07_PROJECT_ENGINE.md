# 07. Project Engine

---

# Purpose

The Project Engine manages all practical work performed by learners.

Projects are not standalone activities. Every project exists to reinforce one or more competencies within a learner's Learning Path.

The Project Engine bridges the gap between theoretical learning and practical application by providing structured, competency-driven project experiences.

---

# Core Philosophy

Projects are competency-driven.

A project exists because it teaches or validates specific competencies.

The workflow is:

Learning Area

↓

Learning Path

↓

Competencies

↓

Project

↓

Logbook

↓

Assessment

↓

Portfolio

---

# Project Ownership

Projects are created by Mentors.

Administrators may also create projects when necessary.

Learners cannot create projects.

---

# Project Types

The system supports:

Individual Projects

Group Projects

Capstone Projects

Institution Projects

Industry Projects

Challenge Projects

Portfolio Projects

---

# Project Structure

Each project contains:

Title

Description

Learning Area

Competency Groups

Target Competencies

Difficulty

Estimated Duration

Expected Outcomes

Required Deliverables

Assessment Criteria

Status

Visibility

Created By

Created Date

---

# Learning Area

Every project belongs to exactly one Learning Area.

Example

Software Engineering

↓

Student Management System

Artificial Intelligence

↓

Crop Disease Detection Model

Cyber Security

↓

Network Vulnerability Assessment

---

# Competency Mapping

Each project must be linked to one or more competencies.

Example

Project:

Hospital Management System

Competencies

✓ Git

✓ REST APIs

✓ Authentication

✓ Database Design

✓ Testing

✓ Deployment

Projects without competencies are invalid.

---

# Competency Groups

Projects may also target Competency Groups.

Example

Backend Development

Frontend Development

Testing

Deployment

This simplifies reporting and mentor assignment.

---

# Project Difficulty

Projects have difficulty levels.

Possible values:

BEGINNER

INTERMEDIATE

ADVANCED

EXPERT

Difficulty should align with the learner's current stage in the Learning Path.

---

# Project Status

Projects may have one of the following statuses:

DRAFT

PUBLISHED

ACTIVE

COMPLETED

ARCHIVED

Only Published projects are visible to learners.

---

# Project Assignment

Projects may be assigned:

To a single learner

To multiple learners

To a cohort

To all learners within a Learning Area

Assignment is managed by Mentors or Administrators.

---

Assigned

Started

In Progress

Submitted

# Deliverables

Each project defines expected deliverables.

Examples:

Source Code

Documentation

Presentation

API Documentation

UI Prototype

Example

Backend API

↓

Authentication

↓

CRUD Operations

↓

Testing

↓

Deployment

# Tasks

Tasks are the smallest work unit.

Each task has:

Title

Description

Status

Deadline

Estimated Hours

Assigned Learner

Completion Date

Tasks support progress tracking.

---

# Evidence Collection

Projects generate evidence.

Evidence includes:

GitHub Repository

Screenshots

Documents

Videos

Presentations

Deployment URLs

Source Code

Certificates

Evidence is reviewed before contributing to the learner's portfolio.

---

# Project Progress

Progress is automatically calculated from:

Completed Tasks

Completed Milestones

Submitted Deliverables

Approved Logbook Entries

Assessment Status

Progress is shown as a percentage.

---

# Mentor Responsibilities

Mentors can:

Create Projects

Assign Projects

Monitor Progress

Review Deliverables

Approve Work

Request Changes

Provide Feedback

Close Projects

---

# Learner Responsibilities

Learners can:

View Assigned Projects

View Requirements

Update Task Progress

Submit Deliverables

Submit Evidence

View Feedback

Track Progress

Learners cannot modify project definitions.

---

# Project Review

Mentors review:

Deliverables

Evidence

Task Completion

Quality

Documentation

Professionalism

Review outcomes:

Approved

Revision Required

Rejected

---

# Project Completion

A project is completed only when:

All required tasks are complete.

All milestones are complete.

Required evidence has been submitted.

Mentor review is approved.

Associated competencies have been assessed.

---

# Portfolio Integration

Completed projects automatically contribute to the learner's portfolio.

Portfolio entries include:

Project Title

Description

Competencies Demonstrated

Evidence

Completion Date

Mentor Feedback

Approved Deliverables

Learners cannot manually add competency-based projects to the portfolio.

---

# Validation Rules

The engine must prevent:

Projects without Learning Areas

Projects without Competencies

Projects without Deliverables

Duplicate Active Assignments

Assignment outside learner Learning Area

Invalid deadlines

Duplicate milestone ordering

---

# Security

Create Projects

Delete Projects

Assign Projects

Archive Projects

Mentors may:

Create Projects

Assign Learners

Review Projects

Approve Deliverables

Learners may:

View Assigned Projects

Submit Deliverables

Upload Evidence

Update Task Progress

---

# Acceptance Criteria

The Project Engine is complete when:

✓ Projects belong to Learning Areas.

✓ Projects map to competencies.

✓ Competency Groups are supported.

✓ Milestones and tasks function correctly.

✓ Deliverables are tracked.

✓ Evidence collection works.

✓ Progress calculates automatically.

✓ Mentor review functions correctly.

✓ Portfolio updates automatically.

✓ Analytics consume project data.

✓ Notifications trigger correctly.
