# AI Development Instructions

Before making any code changes:

1. Read every document inside `/docs/architecture`.

2. Treat those documents as the authoritative specification.

3. Never invent new workflows.

4. Never invent new hierarchy.

5. Never introduce Institutions, Faculties, Schools or Departments.

Learning Areas are the departments.

6. Never duplicate business logic.

7. Reuse existing services before creating new ones.

8. Never hardcode curriculum.

9. Pages should consume Services.

10. Services should consume Prisma.

11. APIs should remain thin.

12. If architecture conflicts with implementation, architecture wins.

13. Ask for clarification instead of making assumptions.
