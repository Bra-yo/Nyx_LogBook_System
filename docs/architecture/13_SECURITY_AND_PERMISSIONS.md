# 13. Security and Permissions

---

# Purpose

The Security and Permissions Engine governs authentication, authorization, access control, data protection, and auditability across BGHub.

Its primary objective is to ensure that every user only accesses resources and performs actions that are explicitly permitted by their assigned role.

Security is enforced at both the UI level and the API level.

No permission should rely solely on hiding interface elements.

---

# Security Principles

The BGHub platform follows these principles:

- Least Privilege
- Role-Based Access Control (RBAC)
- Server-side Authorization
- Auditability
- Data Integrity
- Privacy by Default
- Secure Authentication
- Secure Session Management

# Authorization Model

Authorization is enforced in three layers.

Layer 1

Route Protection

Only authenticated users may access protected pages.

---

Layer 2

Role Verification

Every API validates the requesting user's role.

Example

Learner API

Accessible only by learners.

Mentor API

Accessible only by mentors.

Administrator API

Accessible only by administrators.

---

Layer 3

Ownership Verification

Even if a user has the correct role, they must own the resource.

Examples:

A learner can only view their own logbook.

A mentor can only assess assigned learners.

A mentor cannot review another mentor's learners.

---

# Resource Ownership

Ownership rules include:

Student Profile

Owned by learner.

---

Logbook

Owned by learner.

Reviewed by assigned mentor.

Visible to administrators.

---

Assessment

Created by mentor.

Visible to learner.

Visible to administrator.

Immutable after finalization.

---

Learning Path

Created by administrator.

Visible to learner.

Editable only by administrator.

---

Portfolio

Owned by learner.

Generated by system.

Verified by administrator.

---

# API Security

Every protected API must:

Verify authentication.

Verify role.

Verify ownership.

Validate input.

Return appropriate HTTP status codes.

Never expose internal errors.

---

# Password Policy

Passwords must:

Minimum 8 characters.

Contain uppercase letters.

Contain lowercase letters.

Contain numbers.

Contain special characters.

Passwords must never be stored in plain text.

Passwords must always be hashed.

---

# Session Management

Sessions should:

Expire automatically.

Be invalidated on logout.

Expire after inactivity.

Be securely stored.

Prevent session fixation.

Users may only access information required for their role.

Examples:

Learners cannot access financial records.

Finance cannot access competency assessments.

Mentors cannot access unrelated learners.
