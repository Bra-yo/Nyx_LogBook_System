# BGHub Domain Model

Version: 1.0

Status: Official Architecture

---

# Purpose

This document defines the complete BGHub business domain.

Every database model, API, service, UI, and workflow must follow this document.

No entity may be created outside this architecture without updating this document.

---

# High-Level Domain

BGHub is a Competency-Based Learning Management System.

The domain hierarchy is:

Institution
    ↓
Learning Area
    ↓
Competency
    ↓
Competency Group
    ↓
Learning Path
    ↓
Project
    ↓
Milestone
    ↓
Task
    ↓
Evidence
    ↓
Assessment
    ↓
Portfolio

Although the system may support multiple institutions in future, the learning architecture itself remains identical.

---

# Core Business Entities

## User

Represents every authenticated person.

One user has one role.

Supported roles:

- Administrator
- Mentor
- Learner

A User owns exactly one profile depending on role.

---

## Administrator

Responsible for system configuration.

Administrators manage:

Learning Areas

Competencies

Competency Groups

Learning Paths

Mentor Capacity

Mentor Expertise

Templates

Projects

Reports

Analytics

Administrators never participate as learners.

---

## Mentor

Represents industry supervisors or academic mentors.

Each mentor has:

Expertise

Maximum Capacity

Current Capacity

Availability

Competency Assignments

Allocated Learners

Mentors perform:

Reviews

Assessments

Feedback

Recommendations

Mentors do not create learning architecture.

---

## Learner

Represents a student.

Every learner has:

Admission Number

Learning Area

Learning Paths

Mentor Allocation

Projects

Assessments

Portfolio

Evidence

Logbooks

The learner never creates learning architecture.

# Learning Area

Learning Areas replace traditional academic departments.

Examples:

Software Engineering

Artificial Intelligence

Cyber Security

Networking

Data Science

Cloud Computing

Information Systems

Digital Marketing

UI/UX Design

Mobile Development

A Learning Area contains many Competencies.

Learning Areas may ship with default templates.

Administrators may create additional Learning Areas.

---

# Competency

Competencies define measurable skills.

Examples:

REST APIs

Git

Version Control

React

Flutter

Docker

Machine Learning

Network Security

Python

SQL

Competencies belong to Learning Areas.

Competencies may appear inside multiple Competency Groups.

Competencies should never be duplicated.

---

# Competency Group

Groups organize competencies.

Examples:

Backend Development

Frontend Development

DevOps

Security

Artificial Intelligence

Data Engineering

Each group contains multiple competencies.

---

# Learning Path

Learning Paths connect learners to competencies.

Each Learning Path belongs to:

One Learner

One Competency

Status

Progress

Assigned Mentor

Assessments

Logbooks

Evidence

Learning Paths are generated by administrators.

---

# Mentor Allocation

Connects mentors to learner learning paths.

Each allocation includes:

Mentor

Learning Path

Reason

Status

Assigned Date

Completed Date

History

Allocations are historical.

Old allocations are never deleted.

---

# Mentor Expertise

Defines what a mentor can supervise.

Each mentor may have expertise in:

Learning Areas

Competencies

Competency Groups

The recommendation engine only allocates mentors within their expertise.

Competency Groups

# Forbidden Relationships

The following relationships are prohibited.

Department → Learning Area

Reason:

Departments do not exist in BGHub.

---

Learner → Competency

Direct relationship not allowed.

Must pass through Learning Path.

---

Mentor → Competency

Direct ownership not allowed.

Must use Mentor Expertise.

---

Project → Learner

Direct relationship not allowed.

Must use Learning Path or Project Assignment.

---

Portfolio → Manual Entries

Not allowed.

Portfolio is generated automatically.

---

Duplicate Competencies

Not allowed.

Reuse competencies through Competency Groups.

---

Duplicate Learning Areas

Not allowed.

Administrators extend existing architecture.

# Domain Rules

Every learner belongs to exactly one Learning Area.

Every Learning Path belongs to exactly one Competency.

Every Competency belongs to one Learning Area.

Every Assessment belongs to one Learning Path.

Every Portfolio is generated.

Every Mentor has a capacity limit.

Every Recommendation is reviewable.

Every Competency Progress must be evidence-backed.

Every Analytics value must originate from real records.

---

# Summary

The BGHub domain is centered around measurable competency development.

Learning Areas define disciplines.

Competencies define measurable skills.

Learning Paths define learner journeys.

Projects create experience.

Evidence proves work.

Assessments measure growth.

Portfolios showcase achievement.

Analytics provide insight.

Everything else in the system exists to support this lifecycle.
